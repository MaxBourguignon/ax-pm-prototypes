1. Context

Arenametrix is building a vertical loyalty module for sports and entertainment clubs, powered exclusively by internal Walnut data (Tickets, Purchases, Representations, Link_stats, Campaigns, Targets). The module scores fan engagement by frequency and duration of interactions, expresses that score as a point balance and a tier, and makes both visible and operable inside the CRM. The MVP proves value without external integrations; a future MVP2 will add point redemption, fan-facing portal, app/POS ingestion, and business-impact KPIs.

2. Goals

  1. Measure and value fan engagement via a configurable point-scoring engine driven entirely by Walnut data.
  2. Expose loyalty status (balance, tier, history) directly in the contact card so CRM operators can act on it daily.
  3. Give Marketing Managers a self-serve configuration interface for programme setup, tier definition, and point-earning rules.
  4. Provide a read-only dashboard with key adoption and engagement KPIs for directors and programme owners.
  5. Ensure full traceability of all point movements (batch ingestion, manual adjustments) with admin logs.

Not in scope

  • Point consumption and rewards (loyalty_rewards, redeem_reward(), grants, fulfilment, stock management)
  • Business impact KPIs (before/after activation comparisons)
  • Automatic tier benefits synced to ticketing or e-commerce systems
  • Fan-facing portal and SSO integration (deferred to 2026 upsell)
  • Advanced point expiration engine (per-action expiry, rolling windows)
  • Anti-fraud and duplicate-detection logic
  • CSV export from the dashboard

3. User stories

Story 1 — Activate loyalty programme

As a…Marketing Manager (Programme Admin)
I want to…Create and activate a loyalty programme with a name, start date, eligible segment, and optional expiration
So that…Fan point collection begins automatically for the chosen segment
Acceptance criteriaProgramme requires name, start_date, and eligible_segment; status toggles active/inactive; start_date is locked after activation; eligible segment chosen from existing Arenametrix Targets
Empty stateNo programme exists — full-page empty state with "Create your first loyalty programme" CTA
Error stateMissing required field — inline validation; attempt to edit start_date post-activation — locked field with tooltip
Loading stateSpinner on "Activate" button; page skeleton on initial load

Story 2 — Configure loyalty tiers

FieldValue
As a…Marketing Manager
I want to…Define tiers with name and point thresholds (min/max points), without overlap between tiers
So that…Fans are automatically segmented by loyalty status as their balance grows
Acceptance criteriaAt least 1 tier required before activation; point ranges must not overlap; tier name required; optional badge colour; max_points of highest tier can be null (unlimited)
Empty stateNo tiers defined — "Add your first tier" prompt with example: Bronze / Silver / Gold / Legend
Error stateOverlapping ranges — inline "This range overlaps with [Tier name]"; duplicate name — "A tier with this name already exists"
Loading stateInline save indicator on each tier row

Story 3 — Manage point-earning rules

FieldValue
As a…Marketing Manager
I want to…Configure point-earning rules on a fixed set of action types and toggle rules on/off individually
So that…Fan actions tracked in Walnut are automatically translated into loyalty points
Acceptance criteriaFixed action types: TICKET_PURCHASED, MATCH_ATTENDED, EMAIL_CLICK, SEASON_SUBSCRIPTION; each has points_delta (positive integer), description_internal, is_active toggle; one rule per action_type
Empty stateAll 4 rules shown inactive with placeholder deltas — "Enable at least one rule to start scoring fans"
Error statepoints_delta ≤ 0 or non-integer — inline "Must be a positive whole number"
Loading state"Saving…" replaces "Save all rules" during save

Story 4 — View fan loyalty in contact card

FieldValue
As a…CRM Operator / Fan Relations Agent
I want to…See a fan's point balance, current tier, and last 10 transaction entries in their contact card
So that…I can personalise interactions, create loyalty-based filters, and trigger targeted Brevo campaigns
Acceptance criteriaBalance + tier badge + progress to next tier; last 10 ledger entries (action type, ± points, date, reason for manual); "Modify points" button; Loyalty tier + balance filters in Contacts V2 filter panel
Empty stateFan has no loyalty data — "This contact is not enrolled in any loyalty programme"
Error stateSnapshot API error — "Loyalty data temporarily unavailable" with Retry button
Loading stateSkeleton loader for balance card and history list

Story 5 — Manually adjust fan points

FieldValue
As a…CRM Operator
I want to…Add or deduct points from a fan's balance with a mandatory reason
So that…I can handle commercial gestures and disputes while maintaining a full audit trail
Acceptance criteriaAdjustment modal from Loyalty tab; adjustment_type (Add/Deduct), amount (positive integer), reason (textarea, min 10 chars); new balance previewed; deduction to below 0 shows warning; ledger entry created on confirmation
Empty stateN/A — triggered from loaded contact card
Error stateEmpty reason — "A reason is required (min 10 characters)"; amount = 0 — "Amount must be greater than 0"; submit failure — "Adjustment failed. Please try again."
Loading stateConfirm button shows spinner; disabled during submission

Story 6 — View loyalty reporting dashboard

FieldValue
As a…Director / Marketing Manager
I want to…View a read-only dashboard showing adoption KPIs, tier distribution, and top earning actions
So that…I can track programme dynamics and report on adoption to stakeholders
Acceptance criteriaKPI cards: fans enrolled, % of eligible segment, total points awarded in period, manual adjustments count; tier distribution chart; top 3 actions by points awarded; period selector (30d / 90d / 12m); fully read-only — no export
Empty stateProgramme not activated — "Activate a programme to start seeing data" with link to Settings
Error stateAggregation API unavailable — per-widget "Data unavailable" with last-refresh timestamp
Loading stateKPI card skeletons + chart placeholder + skeleton table rows
