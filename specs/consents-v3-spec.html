Consents V3 — Feature Spec

Product area: CRM Marketing  ·  PM: M. Bourguignon  ·  Fidelity: Near-production
Platform: Web (Arenametrix CRM)  ·  Date: 2026-06-08

⚠ Agent notes: The following were inferred and folded into the spec — happy paths for both stories; empty/error/loading states; the no-reload / export / partial-failure guidelines; the "no consent-definition editing" non-goal; and three derived mock-data entities (evolution series, channel breakdown, activity log). The "Ask AI" CTA is a placeholder only — no behaviour is defined beyond a clickable button.

1. Context

Arenametrix users need to manage consents — lists of contacts who have opted in for a specific purpose (newsletters, SMS promotions), a marketing channel, or a behaviour (analytics) — to stay GDPR-compliant. The primary user is the marketing manager who creates and relies on these consents to segment campaigns; the DPO/compliance officer sits in the background as an audit reader. Today they're stuck on a bare-bones V2 page (Optin Management) that only shows a flat list with technical identifiers: no way to see how a consent evolves over time, no logs, no history. V3 turns that static list into a living, auditable view of consent over time.

2. Goals

  1. Compare the evolution over time of multiple consents side by side.
  2. From any consent, open a detail view exposing its KPIs, evolution chart, and activity log.
  3. At the overview level, understand the breakdown of consents per channel.
  4. Surface KPIs on consent evolution (overall headline strip + per-consent).

Not in scope

  • Launching or executing campaigns / re-opt-in actions from the page — V3 is read/analyse only (at most: create segment or deep-link out).
  • Individual contact activity detail — that lives in the contact record; this page stays at the aggregated level.
  • Hard delete of consents (deactivate only).

4. Screens

ScreenLinked storiesNotes
Consents Overview1, 3 Single scrollable page. Header (title + live consent count; CTAs: options overflow, Export, Ask AI placeholder, Create a consent). KPI strip (active opt-ins + new vs reference date, active consents, opt-in rate; updates with date range). Evolution chart (lighter multi-line; removable consent chips + Add capped at 6 with tooltip; time toggle 3m/6m/12m/since 01/01; updates in place; zero-chips in-chart empty state). Channel-breakdown chart (compact stacked bar / donut beside evolution; share of opt-ins per channel). Consents list (banner rows kept from V2 — name + opt-in-type tag, channel, created date, contacts + trend %, inline sparkline, overflow menu; search + filters; identifier columns removed; deactivated consents show a status tag and stay in list). Row click opens the Detail drawer.
Detail drawer2 Right-side overlay; overview stays visible, dimmed. Header (consent name + opt-in-type tag + channel; close button). Per-consent KPIs (net opt-in trend, opt-in & opt-out rates, contacts). Single-consent evolution chart (lighter). Activity log (system-generated created/updated/deactivated/reactivated events with timestamps + author where available). Export this consent (CSV/PDF). Closes via close button AND clicking the dimmed overview.
Create drawer— Same right-side drawer in create mode. Form to add a consent (name, purpose, channel, opt-in type). Clicking outside with unsaved input asks "Discard this consent?" before closing.
