SMS Management — Feature Spec

Product area: CRM Marketing
PM: M. Bourguignon
Fidelity: Near-production
Platform: Arenametrix web app (CRM Marketing module)
Date: 2026-06-16

1. Context

SMS Management gives marketing managers a native way to create SMS campaigns and analyze their performance directly inside Arenametrix CRM Marketing. Today this is done in an external tool (Brevo), which keeps SMS disconnected from the contact base, segments, and the rest of the customer view — forcing duplicate work and split reporting. The current setup is being replaced now because Brevo offers no interface flexibility and its unicity-key model (SMS + email) clashes with Arenametrix's email-only keys, breaking contact imports on every campaign. The struggle is per-campaign and high-severity: every send means exporting contacts and fighting import/unicity errors in a tool the team can't adapt.

2. Goals

  1. A marketing manager can build an SMS campaign end-to-end (template, segment selection, config) and reach a send/review step — without leaving Arenametrix.
  2. A marketing manager can create and reuse an SMS template.
  3. A marketing manager can view per-campaign performance (messages sent, delivery rate, click rate) and read an analysis of results.

Not in scope

  • The back-end sending mechanics / delivery infrastructure (the actual dispatch); the builder ends at a review/send step.
  • Segment/contact creation — the builder consumes existing CRM segments, it does not create or edit them.
  • Cost, opt-out, and revenue-attribution metrics (V1 KPIs are sent / delivery / click only).

4. Screens

ScreenLinked storiesNotes
Campaigns list1Default tab. Search + status filter + tag filter (filter in place, no reload). Rows: name, status dot (Draft/Sent), last-edited date, #ID, edit, ⋮ menu (Duplicate / Rename / Delete). Click a row → opens campaign in builder (draft) or report (sent). "+ Create campaign" launches the full-page builder.
Campaign builder1Full-page overlay flow launched by CTA. Two-pane: editor (60%) + live phone preview (40%). Sections as a checklist with completion ticks: Message content, Sender, Recipients (existing segment), Config (sending number, send date). Live character/segment counter (xxx/160, n SMS) with special-char/emoji warning, no hard block. Variables highlighted in editor, sample values in preview. "Send test" + "Send" — Send enabled only when required sections complete. Auto-saves as Draft on close.
Statistics2Tab view. Date-range picker scopes the whole view (updates in place). KPI strip: Messages sent (count), Delivery rate (%), Click rate (%). Dataviz: delivery & clicks over time. Per-campaign table (ID / Name / Sent / Delivered % / Clicked % / Date / report) with CSV export. Per-row "report" opens a slide-in side panel over the table; X / click-outside to close.

6. Pre-send checklist

  • Context is one clear paragraph — who, what, why
  • At least 1 goal uses outcome language
  • At least 1 non-goal is stated explicitly
  • Every story has acceptance criteria
  • All 3 edge states are specified for every story
  • Every screen is listed with a description
  • At least 1 mock data entity is defined
  • All open questions have an owner
